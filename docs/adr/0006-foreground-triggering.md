# 按前台应用触发，取消生效栈

ADR-0005 定的栈式恢复，前提是「绑定进程一旦启动就套用预设」，那时多个绑定进程可以同时存在，需要栈来记录叠放顺序。

改成「应用处于前台时才套用」之后，这个前提消失了：同一时刻只有一个前台应用，栈退化成单值。维护一个栈反而带来两个多余的问题——切出再切回要保证压栈/弹栈成对，异常路径下栈深度无从校验。

决定：当前生效曲线 = 前台应用所绑定预设的参数；没有匹配时回到用户当前在界面上调的参数。不设栈，只记住「此刻生效的是哪个预设」。

## Consequences

- alt-tab 切出游戏时，桌面自动恢复自己的曲线，用户看攻略、回消息不再带着游戏滤镜。这是原方案做不到的。
- 每次前台切换触发一次查表写入。实测单次写入 3.5 ms，可接受，但意味着轮询间隔直接决定切换的跟手感。
- 用户正在界面上调参时，如果有绑定应用切到前台，界面上的参数会被临时覆盖，切回来后恢复。这会让滑杆「自己跳」，需要在应用页说明。
- 崩溃自愈仍然只需要写回原始表，不再需要判断栈深度。

## Considered Options

- **保留栈式恢复，只在触发条件里加前台判断**：栈永远不会深于 1，等于给单值套了一层容器，还多出成对维护的风险。

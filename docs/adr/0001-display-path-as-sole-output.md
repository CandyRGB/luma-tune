# 滤镜只通过显示层 Gamma Ramp 输出

参照产品 GammaBoost 不注入任何进程，只调用 `SetDeviceGammaRamp` 写显卡查表，并以「与反作弊零接触」作为核心卖点。替代方案是渲染层（Present 钩子、DXGI 代理、Vulkan 隐式层），能实现单游戏作用域、HDR 调色和完整的 3×3 色彩矩阵，但工程量高一个数量级，且在 Vanguard、Ricochet 这类内核反作弊下存在封禁风险，Facepunch 更是直接禁止 ReShade 启动。本项目由单人开发，作者无 COM 与图形管线经验。

决定 v1 只做显示层。同时把「参数 → Gamma Ramp」的合成层与写入后端解耦，使渲染层未来能作为第二个后端接入，而不改动界面、预设格式与配置系统。

## Consequences

- 滤镜作用于整块显示器，桌面、截图、直播、取色都会一起偏色，这是产品必须坦诚说明的限制。
- HDR 开启时系统忽略 Gamma Ramp，功能直接失效，必须主动检测并明确提示，不能静默无响应。
- 饱和度、锐化、色盲模拟这类需要跨通道运算或外部接口的效果不做（见 ADR-0004），UI 里不出现这些滑杆。
- 换来了零反作弊风险，以及数周内可交付完整产品闭环的可能。

## Considered Options

- **渲染层独占**：能力上限最高，但单人开发周期以季度计，且失败成本是「做完没人敢用」。
- **显示层 + 渲染层并行**：两条后端同时维护，在只有一个开发者时无法收敛。

# 参数体系是固定顺序的算子链

调色参数可以表现为一串有独立数学定义的算子，也可以表现为自由编辑的样条曲线。纯曲线的表达力最强，但无法向用户解释「对比度」对应什么形状，而且滑杆与曲线的双向同步是这类软件最先崩坏的地方。

决定以固定顺序的算子链作为参数的唯一真相，顺序为：

```
输入黑位/白位 → 亮度 → 对比度 → 暗部/高光 → Gamma → 三通道增益 → 曲线 → 输出黑位/白位 → 钳位
```

曲线是链末端的独立算子。滑杆永不读取曲线状态，曲线永不反写滑杆。

输入白位与输出白位分居链首链尾，是因为它们语义不同：输入范围重映射是「把哪一段当成黑白」，输出范围重映射是「最终把黑白放在哪」。合成一个算子会让两者互相干扰——抬高输出黑位之后，输入黑位就再也够不到真正的纯黑了。

## Consequences

- 参数之间存在顺序耦合，调整靠后的算子会改变靠前算子的手感，这是可解释的代价。
- 新效果必须在链上占据固定位置，不能由用户重排。
- 预设只存参数值，不存渲染结果，格式简单，版本兼容容易维持。

## Considered Options

- **纯曲线编辑器**：滑杆与曲线的双向绑定需要维护两套状态并处理相互回写，是这类软件里最先崩坏的部分。
- **暗部用「抬黑位」实现**：直接把整段暗部加一个常量。这会让纯黑变成灰，而用户唯一能补救的输入黑位在链的更前面，够不着。改用端点固定的加权形式，纯黑永远是纯黑。

# 按应用触发采用栈式恢复

> **已被 [ADR-0006](./0006-foreground-triggering.md) 取代。** 触发条件从「进程存在」改为「应用处于前台」之后，同一时刻只有一个前台应用，栈退化为单值，该方案不再成立。

按应用触发的显式做法是「游戏结束就恢复恒等表」。但用户可能已经在桌面上手动调了一条曲线（例如护眼预设），游戏结束时恢复恒等表会把它一并清掉，用户会把这当成 bug，而且很难说清。

决定把生效中的曲线视为一个栈：触发时压入预设曲线，触发结束时弹出并恢复此前那条；只有栈空时才回到恒等表。

## Consequences

- 需要维护一个显式的生效栈，而不是一个「当前曲线」变量。
- 脏标记与栈绑定：栈非空即表示存在未恢复的修改。
- 异常终止后栈深度无从得知，只能整体回到恒等表。这是可接受的降级，因为崩溃时用户已经知道出了事。
